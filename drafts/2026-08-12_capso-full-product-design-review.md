# Capso full-product design review and CleanShot replacement contract

**Date:** 2026-08-12
**Status:** Active product contract; Capso is not yet a full CleanShot replacement
**Scope:** Web app, Mac app, browser extension, account connection, sync, capture, editing, retrieval, sharing and automation

## Executive decision

Capso already has a strong visual system, a credible screenshot library, a useful AI organisation model and a working narrow Mac capture path. It does **not** yet have feature or usability parity with CleanShot X as a whole.

`27_CLEANSHOT_DAILY_DRIVER_PARITY.md` remains useful as the first dogfood milestone. Its explicit exclusions cannot be used as the completion contract for the larger product goal. Full replacement requires all categories in this document to reach `VERIFIED`, including scrolling capture, recording, the full annotation/background workflow, OCR, floating screenshots, history, sharing/security, automation and a legible cross-device sync experience.

The highest-risk gap is not visual polish. It is trust: a capture must survive, explain where it is, show whether it synced, and be recoverable without keeping a browser tab open.

## Definition of parity

Each capability has one of four states:

- `VERIFIED`: production-shaped implementation plus automated evidence where practical and a repeatable physical QA proof.
- `PARTIAL`: a useful path exists, but important states or controls are absent.
- `MISSING`: the user-facing capability does not exist.
- `UNVERIFIED`: implementation exists, but the real signed app/account/device journey has not been proven.

Visual resemblance does not count as parity. A category reaches `VERIFIED` only when the complete job, failure states, keyboard path, accessibility path and persistence semantics are demonstrated.

## Product-wide journey

The replacement journey must read as one product:

1. Capture from Mac or browser.
2. See an immediate, reliable action surface.
3. Copy, save, annotate, pin, share or file without waiting for AI.
4. Let Capso classify and suggest a project in the background.
5. See local/cloud state without learning implementation terminology.
6. Find the capture later by text, visual meaning, project, date or history.
7. Continue on another connected surface with predictable pixel and metadata ownership.

The current product is strongest at steps 4 and 6. Steps 2, 5 and 7 are the main system-design gaps.

## Sync and account experience blueprint

### One visible state model

Every connected surface should use the same states and language:

| State | User-facing message | Primary action |
|---|---|---|
| Disconnected | `Saved on this Mac` | Connect library |
| Connecting | `Connecting…` | Cancel |
| Initial sync | `Syncing 24 captures…` | Keep working |
| Up to date | `Up to date · just now` | Open library |
| Offline/queued | `3 captures saved here, waiting to sync` | Retry when online |
| Auth expired | `Reconnect to sync 3 saved captures` | Reconnect |
| Partial failure | `2 synced · 1 needs attention` | Review issue |
| Unlinking | `Keep cloud copies or remove this device?` | Confirm explicit choice |

Never use `backend`, `worker`, `relay`, `bucket`, `token` or `device code` in the default user journey.

### Ownership semantics

- The Mac original is local-first and survives a cloud delete unless the user explicitly chooses both.
- Cloud pixels are an account-owned copy with clear availability and deletion state.
- Metadata and organisation are account-authoritative once connected.
- Annotation documents are revisioned; flattened exports do not silently replace editable originals.
- Queued captures remain actionable locally while offline.
- A device unlink revokes access without silently deleting local captures or other devices' copies.

### Required surfaces

- Web Settings: device name, platform/version, last seen, sync state, queue, permissions, reconnect and unlink.
- Mac first run: Connect library, local-only choice and an honest explanation of what syncs.
- Mac Account: current state, last success, queued count, Open web library, Retry/Reconnect and sign out semantics.
- Extension: sign in or one-click account pairing, last delivery, outbox and retry.
